新增 API：

### 业务约束补充

- **代理不能录入网吧**：录入入口仅出现在网吧主视角；代理只能通过「关联已审核网吧」进入归属关系
- **未审核网吧不参与匹配**：代理 ID 查询、列表展示均过滤掉 `platformAuditStatus !== 'approved'`
- **铺设前不展示运营数据**：`!launchedAt` 时终端 / 月活 / 流水均显示「⏳ 待铺设」占位，不显示 0
- **删除门店级联**：删除时同时撤销该门店所有 pending 关联/解绑申请（行为不变，与 v2.1 一致）

## 0. 关联模型重构（2026-06-02 更新，v2.1 仍生效）

> ⚠️ 本节变更已覆盖第 2 章「角色体系」与第 4 章「注册流程」中关于关联关系的旧描述。

**核心变化：网吧 ↔ 代理 由静态绑定改为「申请—审批」流程，网吧主与网吧改为 1:N 关系**

### 新数据模型
- `cafe.ownerId`：归属网吧主（必填，录入时落库）
- `cafe.agentId`：已通过审批的代理（可空；空 = 散店）
- `CafeLinkRequest`：关联申请（pending / approved / rejected）

### 新业务流程
1. **代理 / 网吧主各自注册**——注册时不再要求填关联 ID
2. **网吧主在「我的网吧」录入若干门店**——一个店长可管理多家，新录入网吧默认为散店（直连迪越，5% 分成归网吧主）
3. **代理在「关联网吧」页输入网吧 ID 发起关联申请**——附申请理由
4. **网吧主在「我的网吧」页审批待办**——通过 → 该网吧 `agentId` 落库；驳回 → 仍为散店
5. **同一网吧主下的 N 家网吧可分别归属不同代理**：例如 A 网吧给甲代理，B/C/D 网吧给乙代理；未关联的网吧分成归网吧主
6. **一吧一代理**：通过任一申请后，该网吧的其它 pending 申请自动驳回
7. **网吧主可解除关联**：解除后该网吧重新变为散店

### 关键页面与 API
- 代理端新增 `/agent/link-cafes`（`src/pages/agent/LinkCafes.tsx`）
- 网吧主审批入口位于 `/agent/my-cafes`（`MyCafes.tsx` 顶部"待审批的代理关联申请"区，菜单红点提示）
- `mock/data.ts` 新增：`getCafesByAgent / getCafesByOwner / getLinkRequestsForOwner / getLinkRequestsByAgent / requestLinkCafe / approveLinkRequest / rejectLinkRequest / unlinkCafe`
- `CURRENT_AGENT_ID = 'A2001'`、`CURRENT_OWNER_ID = 'O20260215'`（demo 当前账号）

### 散店判定（口径调整）
- **旧**：网吧主 `linkedId` 为空 = 散店（按账号判定）
- **新**：`cafe.agentId` 为空 = 散店（**按网吧判定**）；同一网吧主可同时持有"已关联代理网吧 + 散店"

### 提现策略联动（散店小额自动放行）
- **网吧主 + 全部网吧均为散店 + 可提现金额 ≤ ¥5,000**：免合同自动放行，提现下限放宽至 ¥100
- **任一网吧已关联代理 / 金额 > ¥5,000**：仍走标准合同生效后提现
- 实现位置：`pages/agent/Withdraw.tsx` 的 `ownerAutoApprove` / `STANDALONE_AUTO_LIMIT`
- Dashboard 网吧主侧已新增「已关联代理 / 散店」两个统计卡（紫色 / 蓝色），明确分润口径
- 「我的网吧 / 我托管的网吧」等模块的网吧数从 `agentInfo.cafeCount` 切到动态 `getCafesByAgent / getCafesByOwner` 计算

## 1. 产品定位

面向网吧加盟体系的结算管理平台，归属手助网吧 × 迪越合作项目。核心解决加盟链路中的 **CPS 分成、首装激励、保底结算、合同管理、提现审批** 全流程，覆盖代理、网吧主、运营三类使用方。

平台与应用宝（YYB）打通：注册/实名/银行账户等入驻能力复用 YYB 已有体系。

## 2. 角色体系（4 类参与方）

| 角色 | 身份 | 关联关系 | 结算路径 |
|------|------|----------|----------|
| 超级管理员 | 迪越运营 | 管理全局 | 运营后台操作，审核/放款 |
| 代理 | 企业/个人主体 | 托管多家网吧；可关联已建网吧 | CPS 20% + 阶梯激励 + 保底 |
| 网吧主（关联代理） | 经营网吧 | 注册时关联代理（输入代理 ID，姓名脱敏展示，如「董**」） | CPS 5%，经代理链路 |
| 网吧主（不关联代理 / 散店主） | 经营网吧 | 不关联代理，**直连迪越结算** | CPS 5%，直连迪越 |

> 注册角色仅 **代理 / 网吧主** 两种，不存在独立"散店主"选项；"是否关联代理"在注册时由网吧主自行选择。
> 已明确：**不再关注网吧是否为连锁**，全站无连锁品牌字段与筛选。

## 4. 注册 / 入驻流程（复用 YYB）

复用应用宝注册结构，四大区块：

1. **入驻角色 + 主体类型**：选择 代理/网吧主；个人主体 or 企业主体
2. **实名信息**（人脸/执照校验回填，只读）：姓名、身份证号；企业额外含企业名称、统一社会信用代码
3. **联系方式**：联系人、手机号（验证码，Demo 纯展示）、邮箱（验证码，Demo 纯展示）、省/市、详细联系地址
4. **银行账户**（结算放款）：开户行、银行账号、开户名
5. **关联关系**（可选）：网吧主可关联代理 / 代理可关联网吧 —— 输入对方 ID 精确匹配，姓名脱敏模糊展示
6. **协议**：平台合作协议

注册成功后引导用户**录入网吧**：网吧名称、所在省/市、详细地址、终端数、现场联系人、联系电话、营业时间。新录入网吧默认 `全局结算` + `待审核`，待运营下发渠道号后转区域。

## 5. 结算模型

### 5.1 CPS 分成结构（月结）
- 迪越 25%、代理 20%、网吧主 5%，三方合计 50%，剩余 50% 归应用宝
- 核算依据：终端活跃数据；区域结算（省渠道号分母）+ 全局结算（全国分母）双轨制

### 5.2 首装激励（分摊年金）
- 总额 ¥50/台，分 12 期分摊 ≈ ¥4.17/台/月
- CPS 月均 ¥8.5/台/月，合计单台月单价 ≈ ¥12.67/台/月

### 5.3 代理保底
- 50 元/台 + 2 元/台/月 × 12 = 74 元/台/年；100 台年保底 7,400 元
- 多退少补；提前终止按"保底 × 时间系数"结算

### 5.4 代理阶梯激励（2026 年底前 2000 家）
前 30 家 0 元/台 → 前 100 家 40 元/台 → 前 300 家 30 元/台 → 前 1000 家 20 元/台 → 前 2000 家 10 元/台（均含长期 CPS 20%）

### 5.5 网吧主首装激励

## 6. 区域 / 全局结算口径（关键政策）

### 非对称口径
- **全局池资金**：仅来源于未打渠道号的终端流水
- **全局池分母**：全国所有终端（含已打号）
- **已打号终端**：同时获得「区域 + 全局」双份分成
- **核心推论**：打号 vs 不打号收益差近 8 倍，可作为正向叙事引导代理打号

### 省份分成
- 区域分成按省份落地，每省独立渠道号和结算池
- Demo 数据层保留省份矩阵（`provinceMatrix`），但概览首页已下线展示（跨省代理少见，避免空数据干扰）

## 7. 实现链路（端到端）

```
注册创角（实名+银行+关联） → 录入网吧（待审核） → 运营审核网吧/下发渠道号
        → 终端活跃数据上报 → 月末结算引擎核算（首装分摊 + CPS 分成）
        → 合同闸门校验（无生效合同则锁定提现） → 提现申请
        → 风险分级审批（≤5000 元自动放行秒到，免发票） → 银行放款
```

### 合同闸门（提现前置）
代理录入合同 → 法务审核 → 通过生效 → 解锁提现；驳回则通知修改重提。提现页拦截逻辑：`canWithdraw = contractGate.hasActiveContract`。

### 提现政策
100 元起提；≤5000 元自动放行秒到、免发票；大额走人工审批。散店主（不关联代理）享同等小额自动放行政策。
